# Диагностика и исправление истории и последних заданий

## Причина

Список «Недавно открытые» отсутствовал: в приложении не было хранилища посещений, записи при открытии работы или подписки интерфейса на изменения. Найденный «Журнал отправок» относится к подготовке дневника и не является историей посещений.

Блок «Последние задания» сортировал только по дате в имени папки (`node.date`), игнорируя дату последнего коммита. Поэтому правки старых работ не меняли порядок. В локальном манифесте дата коммита новее даты папки у 109 из 194 заданий; пример — `classwork-2025/c#/03.03`, изменённое 29.09.2026.

## Проверка до исправления

- ID создавался как `p_` + Base64URL нормализованного пути (`stableId`): он не зависит от индекса или содержимого. При переименовании пути ID меняется, поэтому историю нужно сопоставлять по сохранённому пути и удалять невосстановимые записи.
- До исправления не существовало записи посещений; следовательно, не было лимита, дедупликации, сортировки по времени, миграции, обработки `storage`/HashRouter и кнопки очистки.
- Workflow `.github/workflows/deploy.yml` проверяет `main` источника с `fetch-depth: 0`; задания получают дату истории из Git-журнала. Автозапуск расписан каждые 30 минут.
- На момент проверки Actions `37927316762` завершился успешно; SHA `IT-TOP_academy/main`, опубликованный `public/data/content-sha.txt` и локальный манифест совпали: `19e408b7f3ac9935d595c17c6f8a1784bfb75f22`.
- Manifest и `version.json` запрашивались с `cache: 'no-store'`, service worker в проекте нет. Отдельного buildId в URL manifest/search-index не было.

## Исправлено

- Добавлена локальная история последних открытых страниц работ в `localStorage` (`wenwu-recent-visits-v1`): запись после разрешения ID маршрута, merge по ID/пути, сортировка по времени посещения, дедупликация и лимит 20. Старый ключ `wenwu-recently-opened` мигрируется по ID или пути; некорректные и удалённые записи пропускаются. При запрете или ошибках Storage история работает в памяти вкладки, без падения страницы.
- Главная и навигация подписаны на изменения истории внутри вкладки и на событие `storage` между вкладками. Настройки дают очистить историю посещений.
- Дата обновления задания для блока последних работ вычисляется как более поздняя из даты задания в пути и даты последнего коммита; сортировка стабильна при равенстве дат.
- Manifest и поисковый индекс загружаются с buildId в URL и `cache: 'no-store'`; `version.json` запрашивается первым и тоже без кеша.
- Добавлены Vitest-проверки чтения, записи, лимита, дублей, миграции истории, приватного режима, даты обновления и сортировки заданий. E2E проверяет навигацию, настройки и синхронизацию вкладок.

## Проверка после исправления

1. На главной открыть несколько заданий, затем вернуться: они появляются в «Недавно открытые» в порядке посещения; повторное открытие перемещает существующую запись наверх.
2. Открыть «Настройки» внизу страницы и очистить историю; блок на главной и список в боковой навигации обновятся сразу. E2E проверяет изменение из другой вкладки через `storage`.
3. В DevTools Application проверить `wenwu-recent-visits-v1`; заблокированный/очищенный Storage не должен вызывать ошибку приложения.
4. Проверить «Последние задания»: работа с недавним коммитом в старой папке должна учитываться по дате коммита.

Проверки: `npm run lint`, `npm run typecheck`, `npm test` (11 Vitest), `npm run test:e2e` (10 браузерных сценариев), `npm run build`.
