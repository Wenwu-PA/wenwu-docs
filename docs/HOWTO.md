# Краткое руководство

## Новая тема

Добавьте название и варианты исходных имён в `topics.config.yml`:

```yaml
- id: networks
  title: Компьютерные сети
  aliases: [сети, комп сети, networking]
```

После этого запустите `npm run manifest`. Сборщик сопоставляет тему по имени любого каталога в пути.

## Заголовок, условие, метод и статус работы

В папке работы можно добавить YAML-блок в `README.md`:

```yaml
---
title: Два указателя: расстояние между деревьями
topic: algorithms
tags: [two-pointers]
status: in-progress
method: Скользящее окно, время O(N), память O(N)
---
Условие задачи и пояснение решения.
```

Поля также можно хранить в `.archive.yml`. README без метаданных использует первый заголовок Markdown и основной текст.

## Шаблон дневника

На странице материала нажмите «В дневник». Отредактируйте текст, затем скопируйте его или скачайте ZIP. После ручной отправки отметьте работу кнопкой «Отметить отправленной». Шаблон можно сохранить в браузере. Доступные поля: `{{title}}`, `{{topic}}`, `{{type}}`, `{{date}}`, `{{path}}`. Журнал и статус `submitted` хранятся локально на устройстве.

## Кастомный домен

При сборке задайте `VITE_BASE_PATH=/`. DNS и домен настройте в GitHub Pages, затем сохраните `CNAME` в `public/` и замените абсолютный `og:image` в `index.html` на адрес нового домена.

## Перезапуск GitHub Pages

Откройте Actions → `Build and deploy archive` → `Run workflow` на ветке `main`. Локально выполните `npm run content:sync && npm run build`.

## Синхронизация контента локально

`npm run content:sync` выполняет fast-forward pull ветки `main` в `content-src/`. Если вы хотите проверить другую ревизию, переключите только эту временную копию Git и запустите `npm run manifest`.
