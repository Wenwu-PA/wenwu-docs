# Исправление горизонтального переполнения архива

## Воспроизведение

Исходный сайт: `b48b7b3`, контент: `2b299f52c7cc254a771f475c866fe6823ba1db7e`.
Chromium Playwright, светлая тема, viewport 390 × 844, шрифты и PDF загружены.
Страница: `/#/file/p_Y2xhc3N3b3JrLTIwMjYvZW5nbGlzaC8wNy4xMS4yMDI2L1B5dGhvbl9BMV9QcmFjdGljYWxfQ29udmVydGVkLnBkZg`.

После `page.goto(...)` выполнен следующий обход DOM через Playwright:

```js
await page.locator('.pdf-pages canvas').first().waitFor();
await page.evaluate(() => document.fonts.ready);
const result = await page.evaluate(() => ({
  viewport: innerWidth,
  scrollWidth: document.documentElement.scrollWidth,
  elements: [...document.querySelectorAll('*')].map((el) => ({
    tag: el.tagName,
    class: typeof el.className === 'string' ? el.className : '',
    width: el.getBoundingClientRect().width,
    right: el.getBoundingClientRect().right,
  })).filter((el) => el.right > 390),
}));
console.log(JSON.stringify(result, null, 2));
```

Фактический результат **до исправления**:

```json
{
  "viewport": 390,
  "scrollWidth": 423,
  "elements": [
    { "tag": "SPAN", "class": "assignment-path", "width": 399, "right": 423 }
  ]

```

Причина — полный путь `classwork-2026/english/07.11.2026/Python_A1_Practical_Converted.pdf`
во flex-контейнере метаданных без ограничения ширины. PDF canvas сам страницу не расширял.
Регрессионный тест с очень длинным именем дополнительно выявил переполнение текста в крошках
(`SPAN` без класса, ширина 1267, right 1291 на PDF с подменённым именем).

## Исправление

У `.assignment-path` и `.solution-name` заданы `min-width: 0`, `max-width: 100%`
и ellipsis. Полное значение сохраняется в DOM и `title`; заголовок полностью виден с
существующим `overflow-wrap: anywhere`. Крошки используют ellipsis в собственном контейнере.
Перенос кнопок тулбара и ограничения PDF canvas уже существовали и сохранены.
Глобальное скрытие переполнения на `body`/`html` не добавлялось; код сохраняет свой скролл.

Повторный обход исходной страницы после исправления:

```json
{
  "viewport": 390,
  "scrollWidth": 390,
  "elements": [
    { "tag": "SPAN", "class": "", "width": 252, "right": 430 }
  ]
}
```

Оставшийся span — текст внутри крошек с ellipsis: геометрия текстового inline-узла
выходит за границу, но ограничена собственным контейнером и не расширяет документ.

## Большой Jupyter-ноутбук

Лимит 5 MiB больше не запрещает конвертацию `.ipynb`.
Все исходники markdown/code/raw-ячеек сохраняются целиком. Ограничиваются только выводы:
64 KiB на текст/HTML/ошибку, 400 000 байт на вывод с изображением,
суммарно 1 MiB исходных данных выводов на ноутбук. Превышение заменяется типом `hidden`,
пометкой «вывод скрыт: слишком большой» и ссылкой «Скачать оригинал».
Ключ кеша конвертации обновлён, старые результаты не используются.
Большой оригинал доступен через исходную raw-ссылку и не копируется в лёгкий просмотр.

`classwork-2026/base alg/08-10-2026/index.ipynb`:
45 924 887 байт оригинал → 7 067 байт JSON просмотра, 11 ячеек, 1 скрытый вывод.
Предупреждение о превышении лимита исчезло. Повреждённый JSON по-прежнему даёт безопасный fallback.

## Проверки

В `e2e/overflow.spec.ts` добавлены отдельные регрессии для исходного PDF и синтетического
очень длинного имени с пробелами, кириллицей, `#`, `_`, `-` и длинной частью без разделителей.
Обе регрессии выполняются на 390/360 px в светлой/тёмной темах.
На той же матрице проверяются DOCX, Jupyter, код, markdown, изображение и карточка без просмотра.
Тесты ждут содержимое, PDF canvas, шрифты и загрузку изображения; отсутствие образца — ошибка,
а не пропуск. Проверяется также, что `body` не использует `overflow-x: hidden`.
Отдельный e2e проверяет все ячейки большого ноутбука и ссылку скрытого вывода.
Unit-тесты покрывают все три алиаса, сохранность больших исходников ячеек,
ограничение изображений/текста/HTML/ошибок и общий бюджет выводов.

Локальный полный прогон: lint и typecheck успешны, Vitest — 28/28,
Playwright — 30/30 (58,1 с), включая исходный WCAG-аудит (55,8 с).
Production build успешен. `git diff --check` без ошибок.

## Предложение по CI — без изменения workflow

Сейчас `Browser smoke tests` входит в `build`, а `deploy` имеет `needs: build`.
Любая ошибка e2e делает build красным и приводит к skipped deploy.
Это объясняет текущий пропуск; исходное переполнение воспроизводится детерминированно.

Предлагается после согласования:

1. Оставить lint, typecheck, unit и production build блокирующими проверками в `build`.
2. Вынести e2e в отдельный job, не включать его в `deploy.needs`; deploy зависит от успешного build.
3. Для e2e публиковать Playwright HTML report и traces через upload-artifact с `if: always()`;
   писать явный итог в GitHub Step Summary и сохранять красный статус e2e при ошибке.
4. В summary deploy показывать ссылку на e2e job/report, чтобы результат проверки был заметен,
   даже когда публикация разрешена независимо от браузерного теста.

Такое разделение допускает публикацию при провале e2e, в том числе при настоящей UI-регрессии;
это изменение политики требует согласования. `.github/workflows/deploy.yml` не изменён.
